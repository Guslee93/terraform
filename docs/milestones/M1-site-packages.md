# M1 — Site packages and camera

- **Status:** Pending
- **PRD gate:** No live GIS dependency; geometry aligned; stable 3D at target FPS (§13)
- **Lead agent:** `gis-3d-scene-developer`
- **Data agents:** `gis-spatial-data-engineer`, `gis-qa-engineer`, `gis-cartography-designer`, `research-synthesist`
- **Implementers:** `engineering-senior-developer`, `engineering-frontend-developer`
- **Gates:** `engineering-code-reviewer`, `gis-qa-engineer`

## Goal

Ship two curated Oslo demonstration packages as static, versioned assets, loaded through a validated manifest and rendered in the local ENU frame with reliable north orientation and usable camera presets.

## Deliverables

1. **Two packages** — Compact Infill (dense block) and Sloped Edge (topography).
2. **Assets per package** — `manifest.json`, terrain mesh/height samples, context buildings, parcel polygon, context linework, thumbnail, camera presets, sun origin/time zone, constraints, sources.
3. **Manifest contract** — implement `SiteManifest` from PRD §4.1 and validate at load; reject malformed packages with a recoverable error.
4. **Coordinate transform** — one preprocessing script records source EPSG, origin East/North/elevation and the transform. No runtime GIS calls.
5. **Scene layers** — terrain, context buildings, street lines, parcel boundary, setbacks, selected massing, shadow receivers. Toggles with visibility and optional opacity.
6. **Camera** — orbit/pan/zoom, fit site (`F`), perspective/orthographic, presets: Isometric, Top, North, South, Eye Level.
7. **Orientation** — compass, north arrow, scale indication derived from camera; no decorative fake scale.
8. **Performance** — LOD terrain, context mesh instancing or merging, shadow-caster filtering, quality profiles.

## Agent sequence

1. `research-synthesist` verifies dataset licences and records provenance before any asset is committed.
2. `gis-spatial-data-engineer` builds the offline preprocessing pipeline and emits packages.
3. `gis-qa-engineer` validates CRS, topology, north orientation and parcel/context alignment.
4. `gis-cartography-designer` specifies layer legend, north arrow and linework hierarchy.
5. `gis-3d-scene-developer` implements loader, scene layers, cameras and performance profiles.
6. `engineering-senior-developer` implements typed manifest loading and error states.
7. `engineering-code-reviewer` reviews before the gate.

## Acceptance

- Both packages load with no network dependency beyond static assets.
- Parcel and context align visually with the source underlay; north orientation verified by a known bearing.
- Camera presets are deterministic and restore the same view after reload.
- Target > 45 fps at 1440×900 with the reference scene; 60 fps preferred.
- Missing/corrupt asset produces a graceful error, not an indefinite spinner (QA-18).
- Asset budget recorded: total package size, triangle counts, texture memory.

## Out of scope

Live Kartverket/OSM/MapLibre calls, editable parcels, real cadastral boundaries presented as official, synchronized map + 3D dual rendering.

## Evidence

- Package manifest excerpts and licence records.
- Preprocessing command and output checksums.
- Screenshots at all camera presets for both sites.
- Performance trace and triangle/draw-call counts.
- `docs/reviews/M1-code-review.md` and `M1-geometry-qa.md`.

## Risks

- Licensing ambiguity: stop and fictionalize/simplify if republishing rights are unclear.
- Sloped terrain causing mass intersections: explicit base elevation and clearance warnings, no auto-deformation.
- Asset size vs load time: decimate, compress, lazy-load per site.
