## What's already done (don't rebuild it)

`useScenarioProject` owns loading, per-scenario editor sessions, autosave, flush-before-switch and every scenario operation. `StudioShell` already uses it: `project.editor` / `project.dispatch` drive the canvas and panel. The top bar currently shows the active scenario name plus a truthful status from `saveStatusLabel(storage, saveStatus)`. Keep that function and its wording.

### The hook's API (`ScenarioProject`)

| Field | Meaning |
|---|---|
| `ready` | false until the project has loaded; editing is disabled until then |
| `storage` | `'persistent'`, `'memory'` (nothing is saved) or `'read-only'` (the stored data is from a newer version and is never written over) |
| `newerVersion` | the stored format number when `storage === 'read-only'` |
| `skipped` | `SkippedRecord[]` of `{ id, json \| null, reason: 'corrupt' \| 'newer-version' \| 'missing', detail }` — records that couldn't be loaded |
| `scenarios`, `activeId` | ordered documents; the active one is live, including unsaved edits |
| `saveStatus` | `{ state: 'saved' \| 'saving' \| 'unsaved' }` or `{ state: 'error', kind: 'quota' \| 'unavailable' }` |
| `canRemove` | false when only one scenario remains |

`actions`:

| Action | Behaviour |
|---|---|
| `switchTo(id)` | Flushes pending saves; ignored mid-gesture |
| `create()` | Adds "Concept C", D… and activates it |
| `duplicate(id)` | Copies the scenario as "X copy" and activates it |
| `rename(id, name) → string \| null` | Returns an error message or null |
| `setNotes(notes)` | Active scenario only; undoable |
| `remove(id) → Promise<string \| null>` | Returns an error message or null |
| `resetScenario(id)` | Empties the scenario |
| `resetDemo() → Promise` | Back to empty Concept A and B |
| `exportProject() → string` | JSON from what's on screen, including unsaved edits and unreadable records |
| `importProject(json) → Promise` | Throws `ScenarioLoadError { kind, path }` for a bad file, or `Error` when storage is unavailable |
| `discardSkipped(id) → Promise` | Deletes an unreadable record |
| `flush() → Promise` | Saves pending edits now |

`compareScenarios(a, b, site)`:
- Returns `{ rows: CompareRow[], envelope: { a, b }, notes: { a, b } }`.
- Each `CompareRow` is `{ key, label, unit, decimals, a, b, delta }`, where `delta = b − a`, already rounded so it matches the shown values.
- `site` is `{ studyArea, heightAt, constraints }`; `StudioShell` builds the same object for `evaluateEnvelope`, so reuse it.

## C12 — Scenario menu and save status (FR-040, 043, 046, 047)

- **The trigger.** In `StudioTopBar`, the scenario name becomes a disclosure button (`aria-expanded`, `aria-controls`) showing the active scenario's name and a chevron. The save status stays beside it, outside the button.
- **The menu.** A popover anchored under the button, with flat `bg-surface`, a 1 px `border-line` and `rounded-card`:
  - **Scenario list.** One row per scenario: name, a 6 px status dot (amber if the envelope exceeds, green if within), the floor count, and Concept GFA from `scenarioMetrics`. The active row is marked with the accent square and `aria-current`. Clicking a row calls `switchTo`.
  - **Row actions.** Each row has Rename (inline text field: Enter commits and shows the returned error under the field; Esc cancels), Duplicate, Reset (confirmation) and Delete (confirmation, hidden when `!canRemove`).
  - **Footer.** "New scenario" (`create`) and "Reset demo…" (confirmation: "Remove every scenario for this site and start again with empty Concept A and B?").
- **Confirmations.** Use the native `<dialog>` element with `showModal()`, so focus is trapped and Esc cancels. Put the destructive button last and make it the only red element (`text-danger`).
- **Keyboard and focus.**
  - Up/Down move between rows, Enter activates, Esc closes, and focus returns to the trigger.
  - Clicking outside closes the menu.
  - Switching is disabled while a gesture is open, which the hook already ignores; also show the menu items as disabled.
- **Notes (FR-041).** Add a "Notes" field to the panel's Buildings section header area or as its own small panel section, whichever fits the panel order best. It's a `<textarea>` that calls `setNotes` on blur and shows its 2 000-character limit.
- **Tests:**
  - The menu lists the scenarios and switches.
  - Rename shows the duplicate-name error.
  - Delete is unavailable with one scenario.
  - Reset demo needs confirmation.
  - Keyboard: Esc closes and returns focus.
  - Inject a memory repository: `createScenarioRepository(createMemoryStore(), …)`, as in `useScenarioProject.test.ts`.

## C13 — Comparison view (FR-045, 080–084)

- **Opening it.** A "Compare" text action in the top bar, right of the scenario menu, disabled with fewer than two scenarios. It calls `actions.flush()`, then replaces the right panel (the `Inspector`) with a **Compare** panel. The 3D view keeps showing the active scenario.
- **Header.** Two scenario selects, A defaulting to the active scenario and B to the next one, plus a "Close" text button.
- **Thumbnails.** Two thumbnails side by side, both rendered from the **same camera preset** (the current one) and the **same sun date and time** (FR-082, FR-084).
  - Render them with the existing WebGL context; don't create a second one. Add a small capture hook in `src/scene/` (for example `useSnapshot`). It renders scenario A into the canvas off screen with `gl.render` and reads `gl.domElement.toDataURL('image/png')` in the same frame, does the same for B, then restores the live view.
  - Under each thumbnail, label the scenario name and "Same camera · same sun time".
  - If capture fails, which happens on software GL, show the label "Thumbnail unavailable in this browser" instead. Never show a blank or stale image.
- **The comparison table** comes from `compareScenarios`.
  - **Columns:** metric, A, B, then "B − A". Format numbers with the existing `format.ts` helpers.
  - **Deltas:** a sign, a unit and neutral wording: `+800 m²`, `−3.0 m`, `±0`. Use no colour, arrows or "better/worse" wording (FR-081).
  - **Extra rows:** envelope status (`ENVELOPE_STATUS_LABEL`, with "Illustrative constraint — not planning advice" directly below the row) and notes for each side.
- **Activation (FR-083).** An "Edit A" / "Edit B" text button under each thumbnail calls `switchTo(id)` and closes Compare.
- **Accessibility.** The table is a real `<table>` with `<th scope>`. Each thumbnail is an `<img>` whose `alt` names the scenario and the camera view.
- **Tests:**
  - Table values and deltas for two seeded scenarios. Reuse the QA-12 numbers from `src/features/scenarios/compare.test.ts`.
  - "Edit B" switches the active scenario.
  - Compare is disabled with one scenario.
  - The thumbnail fallback text shows when capture throws. Mock the capture function.

## C14 — Recovery and backup (QA-14, FR-048)

- **States.** Show these as a strip at the top of the panel, above the design check: flat `bg-warning-soft`, `text-warning-ink`, sentence case, one line plus actions.
  - **`storage === 'memory'`:** "This browser can't store data, so changes last only until you close the tab." Action: "Export project".
  - **`storage === 'read-only'`:** "These scenarios were saved by a newer version of Terraform (format N) and can't be opened here. Nothing will be overwritten." Action: "Export saved data". You're still working on fresh in-memory Concept A and B.
  - **`skipped.length > 0`:** "N saved scenarios couldn't be opened." Actions: a "Details" disclosure listing each by id, with its reason and `detail`, plus "Export raw data" (the `exportProject()` JSON already contains `unreadable`) and "Discard" (`discardSkipped`, with confirmation).
  - **`saveStatus.state === 'error'`:** the top-bar status already says so. Add "Export project" in the strip, and "Try again" (`flush`).
- **Backup.** In the panel's "Site and sources" group:
  - "Export project" downloads `terraform_<siteId>_<yyyymmdd>.json`, using a `Blob` and a temporary `<a download>`.
  - "Import project…" is a file input. On success, show a one-line confirmation. On `ScenarioLoadError`, show "This file couldn't be imported: <path> <message>"; nothing on screen changes, because the hook only applies a successful import.
  - Ask for confirmation before importing: "Importing replaces every scenario for this site."
- **Tests:**
  - Each strip appears for its state. Drive it with a memory store, `StoreError` and seeded bad rows.
  - Export calls `exportProject`.
  - A bad import shows the error and leaves the scenarios unchanged.
