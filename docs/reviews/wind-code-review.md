## Accepted as-is

- **Coordinate contract:** `flowFrame`, `worldToGrid`, `gridToWorld` and `sampleVelocity` consistently rotate local East/North coordinates into and out of the flow frame; cardinal-direction and inverse-transform fixtures pass.
- **Solver boundary implementation:** inlet/free-stream sides, density-pinned outlet and three-cell obstacle clearance match ADR-0014; canonical cases and the density-stability fixture pass. This is evidence for those fixtures, not engineering validation or proof of stability for every imported layout.
- **Reset/warm-start intent:** frame identity changes reset the solver; geometry changes reuse distributions and reopen the step budget. No demonstrated warm-start failure was found, but existing runner tests do not compare moved/removed obstacles against a cold solve or exercise the full 6,000-step budget.
- **Ownership/lifecycle:** worker messages transfer newly produced velocity and copied solid buffers, leaving solver storage intact; session cleanup terminates the worker; baseline buffers are copied; particle, streamline and circle geometries have disposal cleanup.
- **Domain separation and typing:** solver/grid/comfort/streamline/demo calculations have no React/Three imports; `useWindFlow` is the React adapter. No `any` appears in the scoped files. Particle attribute assertions refer to attributes constructed locally as `BufferAttribute`; retaining typed references would remove the casts, but no failing attribute scenario was found.
- **Derived values and honest scope:** heatmap shares derive from sampled cells, activity bands from explicit thresholds, and downwash is labelled as a rule. The UI does not present the unused annual calculation as measured site climate or annual compliance.
- **Reduced-motion scene:** the viewport listens for preference changes and substitutes settled static streamlines for particles. Streamline tracing runs only when a settled field is rendered, with deterministic seeds and segment obstacle checks.
- **Demo restoration:** stop, completion, keyboard, canvas pointer-down, mode change and camera preset paths restore saved settings; camera effect cleanup restores position/target. Hook tests cover settings restoration and timer cleanup; real-camera restoration is not exercised by those stand-in tests.
- **Control labels:** sliders have associated labels and value text, toggles use native checkboxes, and mode/display buttons expose pressed state; circle placement's completion gap is listed above.
- **Main-thread heatmap cost:** at the maximum 250 m radius, `buildClimateView` generated 12,249 cells in 28.41/10.99/8.97 ms across three Node calls. It resamples and allocates on each worker message; these timings alone do not establish a browser FPS failure. Cache the circle sampling if profiling warrants it.
- **Per-frame allocation assessment:** particles allocate point/velocity/coordinate tuples for 2,500 particles and the demo camera allocates one axis vector per frame. Geometry buffers and the particle colour object are reused; no browser GC/FPS regression was measured, so allocation alone is not reported as a proven failure.

## Verification and limits

- `npm run lint` — **PASS**, exit 0.
- `npm run test` — **PASS**, 96 files / 939 tests, exit 0; reported duration 16.57 s.
- Test output included existing Vite native-config-loader and Three CommonJS deprecation warnings; no test failures.
- Additional probes ran from stdin using an in-memory TypeScript loader; no probe files were created. Performance fixture: 160² frame, centre `[0,0]`, radius 250, margin 1.4; 5,000 buildings of height 12 m and 10 × 10 m footprints at `x=(i%100)*20−1000`, `y=floor(i/100)*20−500`. Timings are local Node observations, not browser acceptance measurements.
- Downwash comparison probe: same frame, west wind, 40 m tower on `[-10,10] × [-10,10]`, identical first 10 solver steps with rule on/off. This isolates the omitted model-setting check; it does not claim those first fields are settled.
- The passing suite does not cover delayed worker delivery/current-input capture, downwash baseline compatibility, collapsed-panel claim visibility, keyboard centre placement, large-site request backlog, or particle endpoint containment. Proposed regression coverage is attached to each finding.
- Build, browser e2e, screenshots and a browser FPS probe were not run: C23 specifically requests lint/test and a single review file. No milestone completion or visual/performance gate is claimed. Pre-existing screenshot deletions and the untracked reference-image directory were left untouched.

## Verdict

**Fail.** The current code gate should remain open until stale baseline capture, incompatible downwash comparisons, missing persistent claims and the demonstrated large-site request backlog are fixed and regression-tested. Address the two minor interaction/rendering defects alongside those fixes, then rerun the applicable acceptance checks.
