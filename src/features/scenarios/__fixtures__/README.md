# M4 persisted-document fixtures (D35)

Generated by `generate.ts` from the **pre-M4** serialiser, so the v0/v1/corrupt/newer files are real format-1 output. `generate.ts` only reproduces them on a checkout from before `cc02494`; on current code `createScenario` already writes format 2, so don't re-run it here. `export-bundle.json` is derived from `export-bundle-legacy.json` with `generate-v2.ts`. `fixtures.test.ts` runs every file through the production migration, repository and import paths.

| File | What it proves |
|---|---|
| `stepped-v1.json` | Real v1 serialiser output for a stepped mass (lower 20×10 m × 3 storeys; upper 10×8 m × 2 storeys at base 9.6 m). Parses and round-trips. |
| `stepped-v0.json` | Same document without `schemaVersion`. Verifies that unversioned docs can be detected and upgraded. |
| `stepped-v2.expected.json` | Expected migration from v1 to v2: `notes: ""`, fixed timestamps, `schemaVersion: 2`, no camera. |
| `corrupt-truncated.json` | Truncated mid-array (invalid JSON). Rejected at path `$`. |
| `corrupt-shape.json` | Valid JSON with a tier missing `footprint`. Rejected with a footprint path. |
| `invalid-geometry.json` | Self-intersecting (bow-tie) footprint. Rejected by `validateScenario` due to crossing edges. |
| `newer-version.json` | `schemaVersion: 99`. Rejected at path `schemaVersion`. |
| `project-index.json` | `ProjectRecord` v2 for `compact-infill` with two scenario IDs, one pointing at a missing file. |
| `export-bundle-legacy.json` | D35's project export bundle: format-2 envelope, but its two scenarios are still format 1. Proves an older bundle still imports and is upgraded. |
| `export-bundle.json` | The same bundle with both scenarios migrated to format 2 (`generate-v2.ts`): a true current export. Used for the FR-048 import/export round trip. |

Generator script: `generate.ts` — run again with `npx tsx` to regenerate from scratch.
